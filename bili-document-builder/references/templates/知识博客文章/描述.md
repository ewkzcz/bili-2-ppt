# 知识博客文章规范

把一批素材整理成**按知识点、专有名词、概念编排**的学习型长文。读者从头读到尾能建立一套完整认知，而不是在查问题。

实际产物长什么样，看同目录的 [案例.md](案例.md)：
取它的层级、颗粒度、图文比例和语气，不取它的主题与内容。

与其他 Markdown 模版（如 [八股模拟面试](../八股模拟面试/描述.md)）的分工：这份回答「这个概念是什么、怎么运作、和什么有关」，那份回答「被问到某个问题怎么答」。同一批素材产出的各份交付物共用同一棵知识树，结论与术语必须一致。



## 结构骨架

```markdown
## {主题}
{开篇：两段以内、200 字以内。只点出这套知识要解决什么问题、
核心矛盾在哪。不设小标题、不写导览、不配图}



### 一、{分类名}

#### 1、{小节名}
{正文}



#### 2、{小节名}
{正文}



### 二、{分类名}
...
```

## 层级规则

- `##` 只有一个：文档标题，写成 `{主题}` 形式（例：`## FastAPI 教程`），不带「一、」这类前缀；
- **文档标题之后直接写开篇正文，不加小标题**。开篇只讲知识本身：
  这套知识要解决什么问题、核心矛盾在哪。**两段以内、200 字以内，不配图**——
  它只是个引入，正文自会展开，在这里铺陈等于把后面的内容提前讲一遍；
  **不要写「学习路线」「按什么顺序学」「时间紧的话先看哪块」这类导览**，
  也不要描述这份文档自己的排版格式（标签行怎么写、哪几段是可选的）——
  那些是写作规范，属于本文件，不属于交付物；
- `###` 只装 `一、二、三…` 编号的分类，通常 4～8 个；
- `####` 装分类下的小节，`1、2、3…` 编号；
- 分类下**只有一个**内容块时，不要硬套 `#### 1、`，正文直接挂在 `###` 下面。



## 标题怎么写

- 功能性、平均偏短。标题回答「这一节在讲什么」，不是「这一节的代号」；
- **禁止固定模版壳**：`相关概念`、`操作步骤`、`完整代码`、`注意点`、`关键问题` 这类空壳标题不要用；
- 疑问句不要做成标题，写在标题下面的首段正文里；
- 涉及同一功能有新旧两套实现时，标题写成 `{功能}-{版本 N 前实现}` / `{功能}-{版本 N+实现}`，版本号写全名（写 `Electron 12` 而不是裸 `12`）。



## 正文形态

- **短叙述 + 小代码**。禁止词典式大表堆砌，也禁止把几百行代码整段倒进来；
- 代码块必须带中文注释，关键配置逐行说明它为什么这么写、改了会怎样；
- 专有名词**第一次出现**时：先用一句人话解释，再给正式定义。不要让读者为了一个没解释的术语停下来；
- **概念之间要有承接**：前一节结尾引出后一节要解决的问题，让整篇读起来是一条线，不是一堆并列词条；
- 对比关系用表格，流程关系用代码块或分步说明，不要用大段文字绕；
- **算式一律写 LaTeX**：出现复杂度、维度关系、计算公式的地方，行内用 `$...$`、独立成行用 `$$...$$`。
  不要把公式写成纯文字——写 `$O(n^2)$` 而不是 `O(n²)`，写 `$\Delta W = A \cdot B$` 而不是 `ΔW = A × B`。
  代码块内的公式不用改。



## 插图

这份文档**不放实拍画面**：它要建立的是概念体系，画面里的命令行与界面截图属于学习笔记PPT。
结构关系一律用 mermaid 画——先后顺序、交互往返、状态迁移、概念层级都算。
主题声明、逐角色配色、收尾纪律见
[references/mermaid-style.md](../../../../references/mermaid-style.md)，所有模版共用同一套口径。

只画材料里能确认的结构。例如材料里出现「请求、调度器、KV Cache、解码器」四个模块，
可以把这四个节点和箭头画出来；材料里没有讲缓存淘汰策略，就不要补画成事实。
拿不准的地方就不画，也不在正文里说明「材料不足」——缺口记进待确认清单，不进交付物。

配图要跟着知识点密度走，不是每节插一张了事：一个分类里一张图都没有，多半是漏了。



## 空行

**章节之间留 3 个空行**：一个小节结束、下一个小节开始之前，空出三条空行当章节边界。
标题与它**自己的正文**之间不留空行——标题下一行直接接第一段；
标题下面直接接小标题时，两个标题之间留 1 个空行。

markdown 会把连续空行折叠成一个，所以 3 个空行在渲染上和 1 个没有区别；写 3 个是为了让
**源文件**里一眼看出章节断在哪里。



## 与素材解耦

正文里不得出现素材的采集痕迹：不写「本集」「这一讲」「讲师」「原片」，不写时间点、编号、来源标注。所有内容读起来应当是一篇独立撰写的技术文章。

也**不要写谈这份文档自身的话**：`这份材料讲两件事`、`全篇按…组织`、`这一页给出…`、
`读者`、`建议按顺序读`、`跳着看`、`学习顺序`。每一句都要在讲知识，不是在讲这篇文章。

同一批素材产出的学习笔记PPT 和其他 Markdown 交付物，术语、结论必须与这份一致；
各份之间不得互相矛盾。改动其中一个结论时，各份一起改。



## 收尾

**不要写复习清单。** 结尾停在最后一个知识点的自然收束处——清单只是把概念标题再列一遍，
读者在目录里已经能看到同样的东西，单独写一节只白占篇幅。
