# 八股模拟面试型文档规范

把素材提炼成**按分类汇编的问答式知识库**，每道题标题下先挂一行标签元信息，
再按需展开不同深度的作答。读者时间紧就只看「简要回答」，有空就往下翻。

实际产物长什么样，看同目录的 [案例.md](案例.md)：
取它的层级、三段的边界、标签行写法和图文比例，不取它的主题与内容。

与其他 Markdown 模版（如 [知识博客文章](../知识博客文章/描述.md)）的分工：这份回答「被问到某个问题怎么答」，那份回答「这个概念本身是什么」。各份交付物共用同一棵知识树，分类、术语、结论必须一致。



## 结构骨架

```markdown
# {主题} 八股模拟面试
{开篇：两段以内、200 字以内。只点出这套知识要解决什么问题、
核心矛盾在哪。不设小标题、不写导览、不配图}

## {分类名}

### Q{n}. {问题}？
> 标签：`#{标签1}` `#{标签2}` | 难度：{⭐1-3 颗} | 频率：{🔥1-3 个}

#### 简要回答
- {分点结论，2-4 条，先给结论或最关键的区分}

> **一句话**：{比简要回答再压缩一层的单句总结}



#### 详细问答
**答：**

{完整展开：是什么、为什么、怎么做、边界在哪、代价是什么、常见的坑；
枚举清点式的事实（比如"分几个区域""分几步"）可以用 `1. 2. 3.` 有序列表，
其余仍用 `-`；该有的对比用表格。}

**追问：**

**Q：** {追问}
**A：** {简短回答}



#### 相关知识
- **定义**：{这道题里核心术语的定义}
- **背景**：{这个机制/概念从哪来、解决什么}
- **易混**：{容易搞混的相邻概念，说清区别}
- **延伸**：{进一步追问或关联知识点}

**坑点：**

- {常见误区或踩坑点}

### Q{n+1}. {问题}
...
```



## 哪些是必选、哪些是可选

**每道题必须有**：标签元信息行、`#### 简要回答`。这是唯一的硬性要求。

**按需选用，不强求每题都带全**：`#### 详细问答`（含**答**/表格/mermaid 图/**追问**）、
`#### 相关知识`（含**定义**/背景/易混/延伸/**坑点**）。判断标准是「这道题值不值得
展开」——概念简单、简要回答已经说全的题，不用硬凑详细问答；容易和别的概念混淆、
或者背后有值得展开的机制，才值得给相关知识。**不要把这几节当成每题必填的表单**，
出现空白凑数的小节比不写更差。

`详细问答` 内部的**答**、`相关知识` 内部的**坑点**、**追问**同理：有实质内容才写，
没有就整段省略，不要写"暂无"这类占位。



## 图、代码与公式

这三样是这份文档的正式组成部分，不是装饰，**缺了内容就讲不透**。

- **图**：内容有先后顺序、交互往返、状态迁移、层级结构或对照关系的题，一律配 mermaid，
  放在 `详细问答` 内部。一篇里配图的比例应该在四成以上——只有纯定义、纯参数这类
  真的没有结构可画的题才不配。一个分类里一张图都没有，多半是漏了。
- **代码**：涉及 API、配置、SQL 的题给**能直接跑的真实代码**，不要伪代码、不要
  `# ...` 省略占位。变量名、函数名、参数名要准确；缺导入就补导入，有截断就补全。
  代码块上方一句话说这段在演示什么，下方一句话说关键行在做什么。
- **公式**：出现算式、复杂度、维度关系的地方**一律写 LaTeX**，行内 `$...$`、
  独立成行 `$$...$$`。不要把公式写成纯文字（写 `$O(n^2)$` 而不是 `O(n²)`，
  写 `$\Delta W = A \cdot B$` 而不是 `ΔW = A × B`）。代码块内的公式不用改。

图按内容选类型，不要全用同一种；主题声明、逐角色配色、收尾纪律都在
[references/mermaid-style.md](../../../../references/mermaid-style.md)，
所有模版共用同一套口径，照那一份写。两张图之间至少隔开一段正文，
连着摆两张读者会当成一张图的两半。



## 标签元信息行的写法

```
> 标签：`#关键词1` `#关键词2` | 难度：⭐⭐ | 频率：🔥🔥🔥
```

- 标签：1-3 个话题关键词，用反引号包住的 `#词` 形式，取这道题真正的技术关键词；
- 难度：⭐（基础）到 ⭐⭐⭐（较难），按这道题本身的理解门槛评，不是按面试出现频率；
- 频率：🔥（较少问到）到 🔥🔥🔥（高频必考），按这类知识点在同类岗位面试里的常见程度估；



## 分类与题面

- **文档标题之后直接写开篇正文，不加小标题**。开篇只讲知识本身：这套知识要解决什么问题、
  核心矛盾在哪。**两段以内、200 字以内，不配图**——它只是个引入，题目自会展开，
  在这里铺陈等于把后面的内容提前讲一遍；
- **开篇不要描述这份文档自己的排版格式**——标签行怎么写、三段哪些是可选的、
  按几个分类编排，这些是写作规范，属于本文件，不属于交付物。读者要的是知识，
  不是这份文档的说明书；
- `##` 装分类，`###` 装问题，题号用 `Q1、Q2、Q3…` 写在标题里——那是标题文字，不是 Markdown 有序列表；
- **题号按分类独立编号**：每个 `##` 分类下都从 `Q1` 重新开始，全篇不连续编号，
  不会出现「二、Q5」这种跨分类接着数的情况；
- **题面必须自包含**：读者不看题号、不记得"第几题是什么"也能读懂。涉及具体对象时把对象写出来；
- 一个分类下按认知顺序排题，不按素材出现顺序排；
- 同类问题合并去重：两道题如果答案有七成重合，就该合成一道，或把其中一道降级成另一道的"相关知识"。



## 写法约束

- 除了"详细问答"里枚举清点式的事实允许用 `1. 2. 3.`，其余步骤与要点列表一律用 `-`；
- 中文技术散文，术语可保留英文；术语首次出现加粗；
- 不写本规范之外的字段标签；
- 不编造：没有依据的量化数字不写，只讲机制与量级关系；难度/频率是主观评级不算编造数据，
  但不要编造具体的"某年某公司考过"这类无法验证的说法；
- 不出现素材采集痕迹：不写来源、编号、时间点、章节引用；
- **只讲知识，不讲这份文档**：不写 `这份材料`、`全篇`、`这一页`、`读者`、`跳着看`、
  `学习顺序`；题与题之间要指路就点题名（「在『按业务形态选引擎』那题里展开」），
  不要写「放到后面第 11 题」。



## 空行

**章节之间留 3 个空行**：一个小节结束、下一个小节开始之前，空出三条空行当章节边界。
标题与它**自己的正文**之间不留空行——标题下一行直接接第一段；
标题下面直接接小标题时，两个标题之间留 1 个空行。
每道题里固定的「简要回答 / 详细问答 / 相关知识」是同一道题的三个部分，不是新章节，
它们前面只留 1 个空行；3 个空行只留在题与题之间、分类与分类之间。

markdown 会把连续空行折叠成一个，所以 3 个空行在渲染上和 1 个没有区别；写 3 个是为了让
**源文件**里一眼看出章节断在哪里。



## 收尾

**不要写自测清单。** 结尾停在最后一个分类的最后一道题上——清单只是把考点再列一遍，
不含新内容，读者翻到这里得不到任何新信息。

要自测，读者会把问题一道道过一遍，这件事本身就不需要单独占一节。
