# 分步动画规范

学习笔记 deck 的分步动画，目的是让讲解能一块一块地展开：先讲这一块，点一下，再出下一块。
它不是特效——动画只用来表达画面上已经确定的先后关系，不把没依据的因果演成事实。

## 为什么是注入 XML

python-pptx 没有动画 API，动画只存在于幻灯片 XML 的 `<p:timing>` 节点里。
所以路线是：先用正常方式把页建好，再让 `scripts/inject_animations.py` 解压 pptx、
往每页写一段 timing、洗掉形状名上的标记、压回去。

不要试图用「一步一页」绕开这件事。拆页和分步是两种东西：拆页会把一页的知识点切成
两页各自不完整的半个图，分步才是一页上逐步展开同一张图。

## 声明方式

建页时把动画组号写进形状名，`deck_kit` 的 `anim=` 参数就是干这个的：

```python
kit.bullets(slide, ["逻辑块是连续的", "物理块可以离散"], x, y, w, h, style.BODY,
            bullet=style.BULLET, anim=1)                          # 第 1 次点击出现
kit.picture(slide, "frames/0042.png", x2, y, w2, h, frame=style.FRAME, anim=2)  # 第 2 次点击出现
```

- **组号**是点击序号，不是形状序号。同一页必须从 1 开始取连续整数。
- **同组一起出**：给多个形状传同一个组号，它们就在同一次点击里同时出现。
  比如先出一条流程箭头、再出箭头上的标注，两者同属第 3 步。
- 形状名最终会被洗掉，不会留在交付物里。

## 三种效果

| 名字 | 表现 | 什么时候用 |
| --- | --- | --- |
| `fade` | 淡入，默认 | 绝大多数情况。两个编辑器支持得最好 |
| `wipe` | 从左擦除 | 表达「流程往右推进」时，方向本身有意义 |
| `appear` | 直接闪现 | 需要干脆利落、不想要过渡感时 |

写法是 `anim="2:wipe"`。不写效果就是 `fade`。

只提供这三种是有意的。学习笔记 deck 要的是「点一下多一块」，不是特效表演；
效果多了反而让读者注意动画本身。

## 一条决定版面的性质

**入场动画只控制「什么时候显示」，元素本身始终在页面上。**

这意味着三件事：

- 渲染成图、打印成 PDF、用别的工具打开，看到的都是**所有元素都可见的完整状态**。
  `render_preview.py` 出的图就是这个状态，所以**渲染图里有重叠，放映时一定也有重叠**。
- 每一页的**最终状态必须是一张完整的、能独立看懂的图**。不能设计成「必须点完 5 次才拼得出一张图」——
  那样静态看这份 deck 的人只会看到一堆碎片。
- 动画步骤只加不减。没有出场动画，也没有「点一下让某个元素消失」。

## 分步数

一页 **2–5 步**。只出一次点击的页不需要标动画。

超过 5 步说明这一页塞了太多概念，应该拆成两页——拆页拆的是知识点，
不是把同一张图切成两半。校验脚本会在超过时提示。

## 自检

```bash
.keyframe-venv/bin/python bili-2-ppt/bili-pptx/scripts/validate_deck.py deck.pptx
```

查四件事：形状名上的声明有没有洗掉、timing 引用的形状 id 是否真实存在、
组号是否连续、有没有没注入的残留声明。

还要人工确认一次：在 PowerPoint 或 WPS 里真的放一遍，点着往下走，
看每一步出来的东西和你要讲的那句话对不对得上。这一步替代不了——
XML 结构合法只说明文件没坏，不说明顺序讲得通。

## 不用动画表达的东西

- 不演「数据在模块之间流动」的过程动画。画面里的流动方向如果没有证据，就不画成事实。
- 不做循环动画、自动播放动画。讲解节奏由讲的人控制，页面不应该自己动。
- 不做强调动画（闪烁、放大）。要强调就在文字里说清楚，不靠动效。
