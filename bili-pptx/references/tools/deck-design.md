# 学习笔记 deck 设计规范

这是一份**学习笔记 deck**：读者要照着学、能反复翻着复习。一页把**一个知识点**讲清楚，
学完这一页能做一件具体的事。

## 从模版取什么

模版原件（`references/<模版名>.pptx` 与 `.html`）是**主题参考**，取的是设计语言：

- **配色角色**：底色、卡片面、墨色三档（标题 / 正文 / 次要）、主强调色、辅助色、点缀色、线色、代码底色，
  以及各色的面积分工（哪些色只作小点缀、哪些色可以铺大块）；
- **字体与字号层级**：标题、正文、等宽字、大号数字各用哪款字体，字号之间的比例，字距与行距；
- **形状语言**：圆角大小、描边粗细、投影（柔和 / 硬投影 / 无）、玻璃透明度、渐变；
- **版头版脚**：眉标记号、标题位置、结论句位置、压线、页码与进度的做法；
- **识别母题与背景**：封面 / 章节页的装饰图形、背景纹理。

**不取原件的内容**：示例姓名单位、示例结论句、章节标题、内容页里的示例图表都是模版方的示范内容，
不进我们的 deck。判据：把这个图形从页面上删掉，这一页讲的内容会不会少一块——会，就是内容，不能照抄；
不会，是装饰或母题，照原件画。

**不取原件的版面**：原件每页怎么排是它那份内容的排法。我们的页面按自己要讲的内容构图，
同一种页型（封面、章节页、目录、内容页）要有多种变体，不要把原件的几页复制过来改字。

## 按内容构图

先看这一页要装什么，再定版面：

| 这一页的内容 | 版面 |
| --- | --- |
| 一次真实运行结果、一份真实数据 | 画面进相框当主体，旁边或下方配结论 |
| 框图、架构图、流水线 | 画面进相框，或用形状重画，原生元素做标注 |
| 要一眼看清的代码 / 表结构 / 参数 | 代码块、表格用原生元素重建 |
| 几个并列概念 | 卡片网格，列数跟项数走（2 / 3 / 4 列），卡高跟字数走 |
| 有先后的步骤 | 编号条目或横向流程 |
| 两种方案对比 | 左右对照栏或对照表 |
| 关键数字 | 大号数字 + 一行说明，数值条画差异 |
| 一句结论或代价 | 提示框单独拎出来 |

- **内容页常见组合**是「图 / 表 / 代码 + 4–6 条『术语：解释』」，卡片写满 2–3 行实质内容，不留半空大框；
- 相邻几页不要同一种版式，流程、对照、表格、代码、数值、画面轮着来；
- 文字量决定尺寸：先用 `deck_kit.text_height()` 估高再定框高，放不下就拆页或换版式，不缩到正文下限以下。

## 画面是页面的主体

**deck 必须根据画面做，不能只根据文字做。** 画面是当时屏幕上真实发生的事——真实数据、命令、
表结构、报错，文字材料替代不了。每一章都要有以真实画面为主体的页面。

- 画面装进模版的相框做法里，按原始比例缩放，不拉伸；相框下方可压一行说明，写这画面**证明了什么**；
- 一页最多两张画面；
- 缩到目标尺寸读不清的（半页宽就糊的代码、挤成一团的表格）改用原生元素重建，
  但不能拿「看不清」当借口把画面全扔掉；
- 重画只画材料里能确认的东西，看不清的字不猜。

## 做教程，不做汇报

- 每页落到可操作的细节：API 调用顺序与参数、配置怎么写、协议字段逐行含义、出错现象与处理；
- 代码给最小可运行片段，注释写这一行为什么这样写；
- 素材只讲到概念层时，按知识树补齐公开规范里能核对的实现细节，不编数据；
- 页序：封面 → 目录 → 各章扉页与内容页。目录每章写一句「学完能做什么」；
  不要总结页、结论页、自测清单页、导览页，最后一页停在最后一个知识点上；
- 篇幅跟知识密度走：一个知识点通常 2–6 页，一页只讲一件事。
  十几个小时的课程成稿在 200–400 页量级，两小时的课只有二十几页就是压成了提纲。

## 字号与字体

- 字号层级照模版原件的比例，教程可读性优先：**要点正文 14pt、卡片正文 13pt、结论句 15pt 起，
  表格 / 图注 / 代码 12pt 起**。原件字号比这小时整体抬一档，层级比例不变；
- 标题与正文要拉开差距；重点靠句内加粗拎出来，不靠放大字号；
- 字体照原件写，西文槽和东亚槽都要写（`deck_kit` 的字体参数给 `{"latin", "ea"}`）；
  只写 latin 时中文会掉回系统默认字体；
- 禁止 `SimHei` / `黑体`、`SimSun` / `宋体`（模版原件自己用的除外），不写本机没装的 `PingFang SC`；
- 做 deck 前先跑 `ensure_fonts.py <模版名>`（命令见 SKILL.md「读模版」），缺的字体能装就装，装不上的照原件字体名写，由打开软件替换显示。

## 配色

- 颜色只用模版原件里出现过的色值，`validate_deck.py` 按 deck 记录的模版逐页核对；
- 照原件的面积分工用色：主色铺多大、点缀色只占多小，都以原件为准；
- 区分并列信息先用墨色三档与强调色的明度差、标签和小标题，不临时引入新色相；
- 正文不用浅灰；深浅底上的文字要有足够对比度。

## 间距与对齐

- 四边留白照原件的页边距，不贴边；
- 内容块之间 0.3 英寸起步；
- 文本框内边距归零（`deck_kit.textbox` 默认如此），文字左边界才能和形状对齐；
- 正文、列表左对齐，只有标题、图例方块里的短标签可以居中；
- 一组同类元素要一致：同层卡片要么都描边要么都不描边，要么都有底色要么都没有。

## 要避免的

- 页面上写「小结」「总结一下」再复述一遍；
- 没有依据的量化数字；
- 整屏代码——只放讲解需要的几行；
- 一页塞满——留白是内容的一部分。

## 自检

先跑校验，再看图：

```bash
.keyframe-venv/bin/python bili-2-ppt/bili-pptx/scripts/validate_deck.py deck.pptx
.keyframe-venv/bin/python bili-2-ppt/bili-pptx/scripts/render_preview.py deck.pptx -o preview/
```

校验拦禁用字体、模版外颜色、动画声明、禁用词和排版硬伤，**不评价版面**。版面必须出图看，当成找茬来做：

- 形状里的文字换行或溢出；文字压线、出框、被盖住；
- 间距不均，有的挤成一团、有的空一大片；
- **框大内容少**：卡片高度超过里面文字高度一倍以上，就把卡片收到与内容匹配，或换版式；
- 同一页几组元素没有对齐；
- 画面在目标尺寸下读不清；
- 和模版原件并排看：配色面积、字体、圆角、投影、版头版脚是不是同一套设计语言。

改完重新渲染受影响的那几页再看，至少完整走一轮「改—再看」。
