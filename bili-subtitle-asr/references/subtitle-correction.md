# 字幕纠错：拿到字幕后立即做，只做这一次

字幕（页面字幕、网页 AI 字幕、音频 ASR）落盘并通过 `validate_asr_output.py` 之后，**立即**按上下文纠错，
产出纠错稿。纠错稿是整条链路唯一的文字输入：知识树、Markdown 交付物、学习笔记PPT 都只读纠错稿，
**下游不再做第二遍纠错**。

为什么必须放在这里做：

- 这时手里有完整的前后文和时间轴，判断同音字、断句最准；到了知识树和 PPT 阶段，
  文字已经被拆散、改写，再回头查错既贵又查不全；
- PPT 阶段 token 消耗极高，任何本该在这里完成的工作拖到那里，都会让那一步变慢、变贵，
  甚至因为「素材有错」被打回重做。**纠错不彻底是本阶段的缺陷，不是下游的返工理由。**

## 一、做什么

逐集、逐段通读，**严格依据上下文**改正下面这些错误：

| 类型 | 例子 | 怎么改 |
| --- | --- | --- |
| 同音字、近音字 | 「大圆模型」→「大语言模型」，「偏置」写成「编制」 | 按前后文推断本来的词 |
| 错别字 | 「部署」写成「布署」，「缓存」写成「缓冲」（语义不对时） | 按正确写法改 |
| 英文术语音译 | 「prefile」→ `prefill`，「拜十」→ `batch`，「page的tension」→ `PagedAttention` | 还原成官方写法 |
| 缩略语 | 「案」→ `EOS`，「SE」→ `SFT` | 按上下文还原 |
| 数字与单位 | 「拜十一」→ `batch 1`，「一百二十八 K」→ `128K` | 数字用阿拉伯数字，单位写全 |
| 人名、产品名、库名 | `pytorch` / `Pytorch` 混用 | 统一成官方写法 |
| 断句与标点 | 一句话被切成两段、没有标点 | 补标点；跨段断开的句子在各自段内补成通顺的半句，不挪动时间轴 |
| 上下文补全 | 识别丢字（「把数据写到里」）、半截话 | 按前后文补上缺的词，补不出就标不确定 |

**先推断，再核对。** 推断依据是本段前后几句、同一集其他位置、同一合集其他集里同一个词的写法，
以及屏幕上可以印证的术语（代码、标题）。核对不了的不要硬改：保留原文并标不确定（见下文），
不要留一个「看着像术语」的错词——那比空着更糟。

**只改识别错误，不改表达。** 口头禅、重复、绕回去补充这些口语问题**不在这里处理**，
留给文档阶段的去口语（见 [narration-refine.md](../../bili-document-builder/references/narration-refine.md)）。
纠错阶段改表达会把讲者原意改丢，也会让时间轴和文字对不上。

## 二、术语表

纠错时同步建立术语表 `glossary.json`，整个合集一份，放在 `$WORK/subtitle/` 顶层（`$WORK` 在系统临时目录下）：

```json
{
  "terms": [
    {"term": "PagedAttention", "aliases": ["page的tension", "配置attention"], "note": "vLLM 的 KV Cache 分页管理"},
    {"term": "prefill", "aliases": ["prefile", "pre fill"]}
  ]
}
```

- `term` 是全文唯一的正确写法；`aliases` 是在原字幕里实际出现过的错误写法；
- 同一个概念只允许一种写法，下游（知识树、交付物）直接照这张表用，不再各自统一术语；
- 纠错稿里不允许再出现任何 `aliases` 中的写法。

## 三、纠错稿格式

每份定时字幕 JSON 旁边写一份同名的 `*.corrected.json`（如 `P03.json` → `P03.corrected.json`）：

```json
{
  "source": "audio-asr",
  "corrected": true,
  "from": "P03.json",
  "segments": [
    {"start": 12.4, "end": 15.9, "text": "prefill 阶段一次处理整段提示词。", "orig": "prefile 阶段一次处理整段提示词"},
    {"start": 15.9, "end": 18.2, "text": "这里的 [?] 需要结合代码确认。", "uncertain": "原文「配置 cash」，疑为 KV Cache 或 page cache"}
  ]
}
```

- **段数、顺序、`start`/`end` 与原字幕完全一致**：一段进、一段出，不合并、不拆分、不挪时间；
- `text` 是纠错后的文本；改动过的段保留 `orig` 原文，便于追溯；
- 核实不了的地方在 `text` 里写 `[?]`，并在 `uncertain` 里写清原文和怀疑方向。
  同时往 `$WORK/pending.jsonl` 追加一条（类型「没听清」，带时间点、上下文和怀疑方向）。
  下游遇到 `[?]` 不回头猜，也不把它写进交付物——那句话只保留确认的部分；
- `source` 沿用原字幕的来源，不因纠错而改变。

## 四、交接前自查

每集纠错完，交给下一阶段之前自己对照一遍，不另跑校验脚本：

- 段数、顺序、时间轴和原字幕一致；
- 术语表里的错误写法在纠错稿里一处不剩；
- 每个 `[?]` 都有对应的 `uncertain` 说明；
- 长字幕一处没改，说明没真正通读——机器转写几乎不可能全对，回去重读。

## 五、下游怎么用

- 知识树、Markdown 交付物、学习笔记PPT **只读 `*.corrected.json` 和 `glossary.json`**，不读原字幕；
- 下游**不再做第二遍纠错**，也不逐句复查错别字。写作中偶然撞见一个漏网的错词，
  就地改掉这一处并补进 `glossary.json`，不因此回头全量复查，也不把整个阶段打回来；
- 画面里能看到、字幕里没有的信息，由画面阶段负责，不在这里凭空补。
